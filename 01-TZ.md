## 3. ОБЯЗАТЕЛЬНЫЕ СКИЛЛЫ В РАБОТЕ

Оба скилла установлены у исполнителя и применяются **на каждой итерации вёрстки**, а не один раз в конце.

### 3.1 Impeccable — `impeccable.style`
- Установка: `npx impeccable install` / Claude Code: `/plugin` → Discover → Impeccable.
- Команды, которые используем:
  - `/impeccable typeset` — после того, как сверстан любой текстовый блок. Приводит типографику в порядок.
  - `/impeccable distill` — когда блок кажется перегруженным. Упрощает.
  - `/impeccable polish` — финальная полировка перед приёмкой секции.
  - `/impeccable live` — точечная правка в интерактиве.
- Детектор ловит 61 анти-паттерн «AI slop». **Ни один флаг детектора не остаётся неразобранным.** Флаги, критичные для нашего стиля: `AI beige`, `italic serif display`, `nested cards`, `pulsing dots`, `hero eyebrow chip`, `GPT thin border wide shadow`.
- Перечень запретов продублирован в `00-DESIGN-SYSTEM.md` §14 — это наш чек-лист.

### 3.2 Taste Skill — `tasteskill.dev`
- Установка: `npx skills add Leonxlnx/taste-skill`. Имя скилла: **`design-taste-frontend`**.
- Порядок применения:
  1. **Context analysis** — скилл читает это ТЗ перед генерацией: индустрия (event/шоу-бизнес), аудитория (B2B + частные), тон (дерзкий, громкий, премиальный).
  2. **Design system choice** — система у нас своя, `00-DESIGN-SYSTEM.md` + `tokens.css`. Скиллу отдаётся она, готовые UI-киты (Material, shadcn и прочие) **не используются**.
  3. **Audit before redesign** — перед стартом прогоняем аудит текущего stastoropov.ru, фиксируем, что сохранить.
  4. **Preflight check** — обязательный прогон перед каждым коммитом секции. Каждый пункт должен пройти честно.
- Тёмная/светлая тема: у нас **нет переключателя тем** — сайт всегда в фирменной схеме. Требование скилла про dark mode закрываем фиксированной тёмной базой с контрастом ≥ 4.5:1, это отмечается в preflight осознанно.

### 3.3 Регламент
Ни одна секция не считается готовой, пока не прошла: `design-taste-frontend` preflight → `/impeccable polish` → ручная проверка по §14 дизайн-системы.

## 4. ТЕХНИЧЕСКИЙ СТЕК

| Слой | Решение | Комментарий |
|---|---|---|
| Сборка | **Vite** | быстрый dev-сервер, простой билд |
| Разметка | HTML + модульные partials (или **Astro**, если нужна многостраничность) | без React — он тут лишний |
| Стили | CSS (native nesting) + `tokens.css` | без Tailwind: стиль авторский, утилитарный фреймворк будет мешать |
| Скролл | **Lenis** | `lerp: .09` |
| Анимация | **GSAP + ScrollTrigger** | reveal, pin, параллакс, счётчики |
| 3D | **three.js** для hero-объекта | фолбэк — `.webm` петля |
| Шрифты | локальные `woff2` в `/fonts` | subset cyrillic+latin |
| Формы | отправка в Telegram-бот + дублирование на почту | без сторонних форм-сервисов |
| Аналитика | Яндекс.Метрика (вебвизор + цели) | цели на каждое целевое действие |
| Хостинг | статика (Vercel / Netlify / текущий хостинг) | домен `stastoropov.ru` остаётся |

**Структура проекта:**
```
/src
  /styles   tokens.css, base.css, sections/*.css
  /scripts  lenis.js, reveal.js, cursor.js, marquee.js, hero3d.js, tilt.js, form.js
  /sections 01-hero.html … 18-footer.html
  /assets   /img /video /fonts /svg(tear, tape, asterisk, barcode)
/public
index.html
```

**Принципы кода:** БЭМ-подобные имена, одна секция = один CSS-файл + один JS-модуль, никаких инлайн-стилей, никаких `!important`, все значения — из `tokens.css`, `prefers-reduced-motion` учтён в каждом модуле анимации.
